# Spec 02 reviews

Three independent reviewer agents read the code at commit `c355399`, each with one lens (correctness, security, design and readability), as `docs/engineering-standards.md` asks. Their findings were merged into one list. This file records each finding, how it was resolved, and the commit or run that resolved it. Findings that belong to spec 02b (the ordering fixes, the EF Core rewrite, the benchmark, removing `LikePattern`, exact-order assertions) are not listed here; that spec covers them.

Status: every finding is resolved except one part of A2, which is a known gap (below and in `parity-report.md`). Where a finding was resolved differently from what the reviewer proposed, the resolution says how and why. The runs are listed in `run-log.md`, session 6.

## B. Security

| # | Finding | Resolution | Commit or run |
|---|---|---|---|
| B1 | `record.yml` runs everything in one job with `contents: write`. | Two jobs. `record` is read-only and uploads the recording as an artifact. `commit` (`needs: record`, `contents: write`) checks the artifact against the manifest and this commit's inputs, adds the state B snapshot and the recording to releases, and pushes. Every checkout that doesn't push has `persist-credentials: false`. | 1aa9614, e3cb906; record [44678822763](https://github.com/iraritchiemeek/nuget-harness/actions/runs/44678822763) |
| B2 | `record.yml` uploads `out/` without a secret scan. | Every upload of `out/` runs after `secret-scan.ps1` and only if it passed. | 1aa9614 |
| B3 | `old-app.yml` uploads check outputs whether or not the secret scan passed (open since spec 01). | The upload is gated on the scan's outcome. | 1aa9614; old-app [44681844424](https://github.com/iraritchiemeek/nuget-harness/actions/runs/44681844424) |
| B4 | No Dependabot configuration. | `.github/dependabot.yml`, weekly, for GitHub Actions (workflows and composite actions) and NuGet. NuGet.Versioning is ignored, because it is held at the old app's version (6.13.2) for parity. **Changed from the proposal:** no `docker` entry. Dependabot's docker updater reads Dockerfiles and compose files, and this repo has none: the images are pinned by digest in scripts, a test fixture and a workflow. The reason is in the file; those digests are updated by hand. | eed3d06, 6869372 |
| B5 | SQL passwords on command lines; the SQL container port bound to all interfaces. | `scripts/linux/sqlcmd.sh` passes passwords through `SQLCMDPASSWORD`, SQL scripts take `$(READER_PASSWORD)` as a variable, `docker run -e` takes names only, and the port is bound to `127.0.0.1`. | eed3d06 |
| B6 | Lint tools and the Testcontainers Ryuk image are not pinned. | PSScriptAnalyzer is checked against the package's SHA-256; ruff is installed with `--require-hashes`. Ryuk is turned off in CI, with the reason in the workflow: each job's runner is thrown away, so nothing is left to reap. | eed3d06, 14c913f |
| B7 | Repository settings (SHA pinning enforcement, rulesets) are not set. | Not applied: repository settings are the owner's decision. Listed as recommendations in `run-log.md`, session 6. | 9548efe |
